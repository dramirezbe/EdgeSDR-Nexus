## Purpose
Build system and deployment: CMake compilation of C binaries, production installation script, systemd unit generation, and dependency management.

## Tech stack & conventions
- CMake for C build system
- Bash scripts for build orchestration
- systemd for service management
- Root-only installation (`sudo`)
- User `anepi` for service execution

## Structure
```
build-deploy/
├── CMakeLists.txt        # CMake build for C binaries (rf_app, ltegps_app, gpiod)
├── build.sh              # Build wrapper (production + dev modes)
├── install.sh            # Production deployment (7 steps, root-only)
├── install-local.sh      # Dev deployment (no systemd, no reboot)
├── init_sys.py           # Systemd unit file generator (7 units)
└── daemons/              # Generated systemd units (gitignored)
```

## Entry points
- `./build.sh` — production build (rf_app + ltegps_app + gpiod)
- `./build.sh -dev` — dev build (rf_app only, stubs gpiod)
- `sudo ./install.sh` — production deployment (build + install + reboot)
- `sudo ./install.sh --no-reboot` — deployment without reboot
- `sudo ./install-local.sh` — dev deployment (venv, no systemd)

## Build Modes

| Mode | Command | Targets | Flags |
|------|---------|---------|-------|
| Production | `./build.sh` | rf_app, ltegps_app | gpiod included |
| Development | `./build.sh -dev` | rf_app only | `-DBUILD_STANDALONE=ON` (stubs gpiod) |

## Install Steps (install.sh)

| Step | Actions |
|------|---------|
| 1. Stop services | Stop all active `-ane2.service` units except ltegps |
| 2. Dependencies | apt-get install ZMQ, cJSON, libcurl, libusb, fftw3, GStreamer, Opus, Python3 |
| 3. Hardware libs | Compile libgpiod v2 + kalibrate-hackrf from source if not detected |
| 4. Python env | Create venv, install pip + certifi + requirements.txt, run build.sh |
| 5. Shared memory | Initialize `/dev/shm/persistent.json` as `{}` with permissions 666 |
| 6. Systemd | Run init_sys.py, copy daemons to `/etc/systemd/system/`, enable + daemon-reload |
| 7. Reboot | Immediate reboot to start all services fresh |

## Systemd Units (generated by init_sys.py)

| Unit | Type | Description |
|------|------|-------------|
| rf-ane2.service | Service | C RF engine, Restart=always, flock-guarded |
| ltegps-ane2.service | Service | C LTE/GPS engine, Restart=always |
| orchestrator-ane2.service | Service | Python orchestrator, Restart=always, pre-checks internet |
| status-ane2.service | Oneshot | Status reporter, invoked by timer |
| status-ane2.timer | Timer | 30s interval + 1 min after boot |
| retry-queue-ane2.service | Oneshot | Queue processor, invoked by timer |
| retry-queue-ane2.timer | Timer | 300s interval + 1 min after boot |

## Key interactions
- **install.sh** calls `build.sh` internally
- **install.sh** calls `init_sys.py` to generate systemd units
- **install.sh** copies generated units to `/etc/systemd/system/`
- **Build artifacts** (`rf_app`, `ltegps_app`) placed in repo root by build.sh

## Common tasks & gotchas
- `install.sh` logs every run to `Logs/install_YYYYMMDD_HHMMSS.log`
- On failure, `install.sh` restarts any services it stopped before aborting
- Python deps reuse venv when `requirements.txt` is unchanged (stamp: `venv/.requirements.sha256`)
- `init_sys.py` generates units into `daemons/` — these are gitignored
- Build artifacts are placed in repo root — also gitignored
- `--no-reboot` flag keeps ltegps on old binary until manual restart
